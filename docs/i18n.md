# Internationalization (i18n)

Nastolka supports English (`en`), Polish (`pl`), and Russian (`ru`) via [vue-i18n](https://vue-i18n.intlify.dev/).

## File locations

- `src/i18n/index.js` — `createI18n(...)` setup, locale detection/persistence (`detectLocale`, `setLocale`), and a standalone `t` export for non-component code.
- `src/i18n/locales/en.json`, `pl.json`, `ru.json` — the translated message catalogs, one file per locale.
- `src/components/LanguageSwitcher.vue` — the EN/PL/RU toggle, mounted globally from `App.vue` so it's visible on every route, including pre-login (Login/Register).

## Naming convention

Keys are namespaced one level per view, matching the view's filename in camelCase (e.g. `LocationDetail.vue` → `locationDetail`). Views with several sub-components nest by feature area under that namespace instead of creating a namespace per file — e.g. `locationDetail.games.*` covers `GamesPanel.vue` and `GameCard.vue`, `locationDetail.history.*` and `locationDetail.historyEntry.*` cover the history panel/card, `locationDetail.sharing.*` covers `SharingPanel.vue`.

Strings repeated verbatim across unrelated views (button labels like "Delete"/"Cancel", generic "Try again", the "Back to {name}" pattern, the history-state labels) live under `common` instead of being duplicated per namespace.

## Adding a new translatable string

1. Add the key to `src/i18n/locales/en.json` under the right namespace (create a new namespace if it's a new view).
2. Add the **same key path** to `pl.json` and `ru.json` with the translated value. Key order doesn't matter to vue-i18n, but keeping it consistent across the three files makes diffs easier to review.
3. Use it:
   - In a `<template>`: `{{ $t('namespace.key') }}` (or `:placeholder="$t('namespace.key')"`, etc.) — no import needed, `$t`/`$d` are globally injected.
   - In `<script setup>` logic (confirm dialogs, thrown errors, computed labels): `import { useI18n } from 'vue-i18n'; const { t } = useI18n()`, then `t('namespace.key')`.
   - In a plain `.js` file that isn't a component (a composable, the Pinia store): `import { t } from '<path to>/i18n'` — these can't call `useI18n()` since they don't run inside a component's `setup()`.
4. **Interpolation**: pass a params object, e.g. `t('common.backTo', { name: location.name })` for a message defined as `"Back to {name}"`.
5. **Pluralization**: write the message with vue-i18n's pipe syntax (`"{count} pt | {count} pts"` for English 2-form; Russian/Polish need 3 forms — one/few/many, e.g. `"{count} балл | {count} балла | {count} баллов"`), then call `t(key, { count }, count)` — **named params first, plural count second**. Russian and Polish plural category selection is handled by the custom `pluralRules` registered in `src/i18n/index.js` (the vue-i18n default rule doesn't handle Slavic one/few/many correctly).
6. **Dates**: use `$d(date, 'short')` (see the `datetimeFormats` registered in `src/i18n/index.js`) instead of `Date.prototype.toLocaleString()`, so date formatting follows the in-app language selection rather than the browser's own locale.

## Known limitation

Error messages returned by the backend API (`e.message` from a failed `fetch`) are shown as-is and are **not** translated by this setup — only the local fallback string (`e.message || t('namespace.key')`) is. Localizing backend error messages would require changes on the API side.

## Verifying translations

vue-i18n logs a console warning (`[intlify] Not found 'X' key in 'Y' locale messages`) whenever a key is missing for the active locale. Switch through `en`/`pl`/`ru` (via the switcher, or `localStorage.setItem('nastolka-locale', 'pl')` + reload) and click through the app with devtools open — a clean console means no missing keys.

## Adding a new locale

1. Create `src/i18n/locales/<code>.json` with the full key set copied from `en.json`, translated.
2. Add `<code>` to `SUPPORTED_LOCALES` in `src/i18n/index.js`.
3. Import the new file and add it to the `messages` object (and a `datetimeFormats` entry) passed to `createI18n(...)`.
4. Add a label for it to `LanguageSwitcher.vue`'s `LABELS` map.
5. If the locale uses non-English/Russian/Polish plural rules, add a `pluralRules` entry for it too.
